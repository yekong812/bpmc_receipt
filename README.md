# BPMC 통합 지출 관리

[v4 통합 개발 계획서](bpmc_receipt_integrated_development_plan_v4.md)를 바탕으로 만든 로컬 웹 애플리케이션입니다. Next.js + TypeScript 프런트엔드, FastAPI + SQLAlchemy + SQLite 백엔드로 구성합니다.

## 구현 기능

- **행사비 / 경상비 / B** 메뉴, 모바일 가로 메뉴·데스크톱 사이드바
- 경상비·B 연도별 독립 장부, 연도 중복 생성 방지·연도 혼입 차단
- 경상비 관·항·목 예산 관리, 확정 거래 기준 실지출·잔액·집행률 및 항별 소계
- B 수입·지출·이월금·캐시백 구분, 이월 포함/제외 집계와 전년도 잔액 참고
- 이전 연도 예산·항목만 복사, 거래·영수증 복사 없음
- 연도별 예산/장부 Excel 미리보기·매핑·추가/대체·내보내기
- 공통 **PPTX 증빙자료**: 16:9, 슬라이드당 3장, 비율 유지·중앙 배치, 20장 → 7슬라이드
- 행사 항목·경상비 관/항/목을 AI 컨텍스트로 전달해 분류 후보 제안, B는 분류 생략
- 장부별 고정 영수증 번호, 다른 장부의 동일 영수증 재사용 확인, 이미지 개별 업로드

- 행사 날짜와 관리기간을 별도 저장, 행사 생성·수정·복제·삭제, 날짜·기간·상태 필터, 정렬·페이지 이동
- 대형 지출내역 모달, 9개 기본 컬럼, 행 추가·복제·선택 삭제·일괄 저장
- 실시간 전체/항목별 합계, 영수증 배분금액 차이 안내·메모, 미저장 경고
- 임시 저장 → 최종 확정 → 수정 재오픈 → 재확정
- 불변 확정 버전과 원본 이미지 별도 보관, 버전별 Excel/ZIP 다운로드, 변경 이력
- 행사별 항목 이름·색상·순서·활성 상태, 사용 항목 이동 후 삭제, 다른 행사 항목 복사
- Excel 헤더 탐색·사용자 열 매핑·미리보기·검증·항목 매핑/생성/제외·추가/대체
- 서식과 항목 드롭다운을 적용한 `.xlsx` 내보내기, 영수증 목록 시트, 왕복 호환
- 영수증 ZIP 안전 검사, 이미지 원본 저장·미리보기, SHA-256이 같은 파일은 원본 번호를 검토 사유에 기록하고 제외 상태로 등록
- OpenAI Responses API 연동: OCR 텍스트 보완 / 영수증 이미지 직접 분석, 사용량·추정 비용·실패 사유 기록
- 선택 설치 PaddleOCR 연동, 영속 작업 ID/진행률 조회, 규칙 기반 날짜·시간·금액 후보 추출
- OCR 결과로 지출 초안 자동 생성, 중복 매칭 후보는 신규 행 생성 보류, 사용자 수정값 재분석 보호
- OCR 원문·추출 이력·사용자 수정값 비교, 사용자 선택으로 후보값 적용
- 추출값 수동 검토, 매칭 후보 제안, 사용자 승인 연결, 다대다 배분액 검증
- 확인한 영수증으로 지출 생성, 거래일시순 `1_5000.png` 형식의 ZIP 다운로드
- Alembic 초기 마이그레이션, 트랜잭션과 버전 검사로 실패·동시 수정 보호

## 로컬 실행

기본 실행은 Node.js 22와 Python 3.11 이상이 필요합니다. **로컬 PaddleOCR까지 사용하려면 Python 3.11 환경을 권장합니다. 외부 LLM의 이미지 분석은 PaddleOCR 없이 사용할 수 있습니다.** 이 작업 환경의 Python 3.14에서는 기본 API를 검증했고 PaddleOCR는 설치하지 않았습니다.

프로젝트 루트에서:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
cd frontend
npm ci
cd ..
./scripts/dev.sh
```

화면: **http://127.0.0.1:3000**  
API 문서: http://127.0.0.1:8000/docs

`venv` 생성 시 `ensurepip`가 없다는 메시지가 나오면 해당 Python 버전의 `venv` 패키지를 먼저 설치하세요. 예: Ubuntu의 `python3.11-venv`.

서버를 각각 실행할 수도 있습니다.

```bash
# 터미널 1 — 프로젝트 루트
.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --reload

# 터미널 2
cd frontend
npm run dev
```

백엔드 시작 시 마이그레이션을 적용합니다. 기존 SQLite DB에 변경을 적용하기 전에는 `storage/backups/`에 자동 백업을 만듭니다. 사용자 설정 `STORAGE_DIR`가 있으면 그 경로의 `backups/`를 사용합니다. 별도 샘플 데이터는 주입하지 않습니다. 화면에서 새 행사를 만들어 시작하세요.

환경변수 예시는 [.env.example](.env.example)을 참고하세요. API에 파일로 전달하려면 `uvicorn ... --env-file .env`를 사용합니다. 프런트엔드의 `API_BASE_URL`은 `frontend/.env.local` 또는 프로세스 환경에 설정하고, 운영 빌드에서는 빌드 전에 지정하세요.

## v4 메뉴 사용법

화면 왼쪽 메뉴(모바일은 상단)에서 **행사비 / 경상비 / B**를 선택합니다. 직접 주소는 `/events`, `/ordinary`, `/b`입니다. 기존 `/` 주소도 행사비 화면을 유지합니다.

### 행사비

기존 행사 생성 → 상세 팝업 → 영수증 분석·지출 편집 → 임시 저장 → 최종 확정 순서로 진행합니다. 상세 팝업과 영수증 탭에서 PPTX를 다운로드할 수 있고, 변경 이력에서도 이전 확정 버전의 PPTX를 출력할 수 있습니다.

### 경상비

1. **연도별 장부 생성**에서 연도를 지정합니다. 빈 예산표로 시작하거나 다른 연도의 **예산·항목만** 복사할 수 있습니다. 거래와 영수증은 복사하지 않습니다.
2. **예산 현황**에서 `관 → 항 → 목` 순서로 추가합니다. 관·항 명칭은 계층 관리에서 수정하고, 목별 예산·세부내용을 입력한 후 **임시 저장**합니다. 관 명칭은 사용자 설정값이며 임의의 업무 명칭을 고정하지 않습니다.
3. **경상비 장부**에서 날짜·항·목·내용·수입·지출을 입력합니다. 항 선택에 따라 목 목록이 달라집니다. 한 행에는 수입 또는 지출 한쪽만 입력합니다.
4. **영수증 관리**에서 이미지 또는 ZIP 업로드 → 영수증 분석을 실행하면 지출 초안을 생성합니다. AI는 해당 연도의 활성 목 목록 안에서만 분류 후보를 제안합니다. 분류가 불확실하면 목을 직접 지정하세요.
5. 거래를 클릭하면 거래유형·검토 완료·영수증 없음/금액 차이 사유를 수정할 수 있습니다. **임시 저장 → 최종 확정** 순서로 진행합니다.
6. 예산표의 공식 실지출은 **최신 확정본 거래만** 반영합니다. 초안 지출은 ‘편집 중’으로 별도 표시하며 공식 집계에 더하지 않습니다. 예산 0원의 집행률은 `—`로 표시합니다.
7. 사용 중이거나 확정본에서 참조한 목은 삭제를 차단합니다. 과거 연결을 유지하려면 비활성화하세요. 현재 거래를 다른 목으로 변경해 저장할 수 있으며, 확정 이력은 원래 항목을 보존합니다.

### B

연도별 장부를 생성하고 `날짜 / 내용 / 수입 / 지출 / 영수증번호`를 편집합니다. 예산표·관·항·목은 없습니다. 수입은 수동 입력하고, 영수증 분석은 지출 초안으로 반영합니다.

거래를 클릭한 뒤 거래유형을 **일반 수입 / 지출 / 이월금 / 캐시백**으로 구분합니다. 새 연도 생성 화면은 전년도 **확정 잔액을 참고값으로만** 표시합니다. 이월금은 사용자가 직접 등록·승인해야 하며 자동으로 수입에 추가하지 않습니다. 공식 총수입과 차액은 ‘이월금 제외’ 옵션으로 구분할 수 있습니다.

### Excel 및 출력 기간

- 경상비 Excel: 선택 연도의 `예산 현황`과 `경상비 장부` 시트를 함께 출력합니다. 예산의 실지출은 연간 공식 값이므로 경상비 Excel은 항상 연도 전체 기준입니다.
- 교회 장부 Excel: 경상비에서 거래가 있는 첫 달부터 마지막 달까지 월별 시트를 만듭니다. 첫 달은 입력된 이월금으로 시작하고, 이후에는 전월 잔액이 넘어갑니다. 월계에는 해당 달의 입금·출금만 포함합니다. 날짜가 없는 거래는 별도 시트에 표시합니다.
- B Excel: 선택 연도와 출력 기간의 거래를 출력합니다. 보이는 5개 기본 컬럼 외에 숨김 `거래유형` 열로 이월금·캐시백을 왕복 보존합니다.
- 경상비 예산 탭에서 가져오면 **예산표**, 장부 탭에서 가져오면 **거래**를 미리보기합니다. 다른 시트·헤더는 시트 선택과 열 번호 매핑으로 지정합니다. 경상비 거래 Import 전에 해당 연도 관·항·목을 설정하세요.
- Excel 파일의 실지출과 확정 장부 합계가 다르면 경고하고, 파일의 실지출을 예산 실지출로 덮어쓰지 않습니다.
- 추가/대체는 사용자 확인 후 트랜잭션으로 반영하며, 이전 상태는 `import_backup` 변경 이력에 보관합니다. 다른 연도 날짜는 반영을 차단합니다.
- 기간 필터는 **경상비·B의 PPTX/ZIP 및 B Excel**에 적용됩니다. 기간은 선택 연도 안에서 지정합니다.

## PPTX 영수증 증빙자료

각 메뉴에서 **PPTX**를 선택합니다. 출력은 저장된 값을 사용하며 AI를 다시 호출하지 않습니다.

- 16:9 와이드, 슬라이드당 최대 3장, 마지막 1~2장도 중앙 배치
- 이미지 방향 보정·원본 비율 유지, 자르거나 늘리지 않음
- 제목·페이지 번호와 **장부 영수증번호 / 거래 날짜·시간 / 구매처 / 최종금액** 캡션은 작게 배치해 이미지 공간을 확보합니다.
- 거래일시·원본명 순서로 배치하지만 캡션은 **고정 영수증번호**를 유지합니다. 날짜 수정으로 표시 순서가 바뀌어도 연결 ID와 참조 번호는 바뀌지 않습니다.
- 기본은 최신 확정본. 확정본이 없으면 `DRAFT_` 파일명과 `[미확정 초안]` 제목으로 출력합니다. 과거 확정본은 변경 이력에서 선택합니다.
- 날짜·시간·금액 또는 검토 상태가 미확인인 영수증은 기본 출력에서 오류로 안내합니다. 사용자가 **PPT 미확인 포함**을 선택하면 확인되지 않은 상태를 캡션에 표시해 포함합니다. 중복 제외 영수증은 출력하지 않습니다.
- 기간에 맞는 영수증이 없거나 이미지가 손상·누락되었으면 전체 생성에 오류를 표시합니다. 문제 이미지를 조용히 건너뛰지 않습니다.
- PPTX는 표시용으로 이미지를 변환할 수 있습니다. ZIP은 원본 확장자와 파일 바이트를 보존합니다.

PPT 생성은 [python-pptx 공식 문서](https://python-pptx.readthedocs.io/en/latest/user/quickstart.html)를 기준으로 구현했습니다. 매우 긴 영수증의 1장 확대 레이아웃은 후속 옵션입니다.

## OCR 실행

Python 3.11 가상환경에서:

```bash
.venv/bin/python -m pip install -r backend/requirements-ocr.txt
```

서버를 재시작하고 영수증 관리 탭에서 ZIP 업로드 → 영수증 분석 시작 → 원본과 추출값 검토 → 검토값 저장 → 지출 연결 순서로 진행합니다. 첫 분석 때 모델 다운로드와 초기화가 필요하므로 인터넷 연결이 필요하며, 이후 로컬 OCR를 사용합니다.

엔진 미설치나 분석 실패는 영수증에 사유를 표시하며 수동 입력으로 계속 사용할 수 있습니다. OCR 결과는 항상 사용자 검토를 거칩니다. 날짜·시간은 임의로 채우지 않으며, 결제금액 후보가 여러 개면 확정하지 않습니다. 취소·환불은 검토 대상으로 표시합니다.

작업 진행률·영수증별 결과·수정값·분석 이력은 SQLite에 저장합니다. 서버 재시작 시 실행 중이던 작업은 중단 상태로 표시합니다. 목록에서 저장된 결과를 확인하고 다시 분석할 수 있습니다. OCR 실행은 한 번에 한 작업씩 처리하며 다중 worker 실행은 지원하지 않습니다. 사용자 수정값은 재분석으로 덮어쓰지 않습니다.

## 외부 LLM 연결: OpenAI

**PaddleOCR를 설치하지 않아도 `vision` 모드에서 영수증 이미지를 직접 분석할 수 있습니다.** 추출 대상은 거래 날짜·시간, 상호, 구매 내역, 원화 최종 결제금액입니다. v4 기본 모드 `vision`은 행사별 항목 또는 경상비 목 분류까지 한 번에 요청하며 B는 분류 없이 반영합니다. 분석 후 지출 초안을 생성하며 최종 확정은 사용자가 수행합니다.

### 1. API 키와 환경변수 설정

[OpenAI API 키 관리](https://platform.openai.com/api-keys)에서 발급한 키를 준비합니다. 프로젝트 루트의 `.env.example`을 참고해 `.env`를 만드세요. 기존 `.env`가 있으면 아래 항목을 추가·수정합니다.

```bash
# 처음 설정할 때만 실행
cp .env.example .env
```

PaddleOCR 없이 이미지 직접 분석을 사용하는 예시:

```dotenv
RECEIPT_LLM_ENABLED=true
OPENAI_API_KEY=sk-여기에_실제_API_키
OPENAI_MODEL=gpt-4.1-mini
RECEIPT_LLM_MODE=vision
RECEIPT_LLM_ALLOW_IMAGES=true
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_TIMEOUT_SECONDS=60
```

`.env`는 Git에서 제외됩니다. API 키는 **프로젝트 루트의 서버용 `.env`에만** 넣고 `NEXT_PUBLIC_` 변수나 프런트엔드 코드에 넣지 마세요. 키 값 자체는 상태 API·분석 이력·오류 메시지에 기록하지 않습니다.

### 2. 서버 실행 및 적용

```bash

```

개발 스크립트는 루트 `.env`가 있으면 백엔드에 자동 로드합니다. 환경변수를 바꾸면 실행 중인 서버를 종료하고 다시 실행하세요. 서버를 직접 실행할 때는 파일을 명시합니다.

```

Docker Compose도 루트 `.env` 값을 백엔드 환경에 전달하도록 설정되어 있습니다.

# .env만 변경한 경우에도 컨테이너 환경 갱신 필요

```

`vision`은 `INSTALL_OCR=false` 기본 이미지로 동작합니다. `auto/text`에서 로컬 OCR를 사용하려면 `INSTALL_OCR=true docker compose up --build -d`로 설치합니다.

### 3. 화면에서 사용

행사 상세 또는 연도별 장부 → **영수증 관리**에서 이미지나 ZIP을 업로드하면 새로 등록된 분석 대기 영수증이 자동으로 체크됩니다. **영수증 분석 시작**을 누르면 체크한 영수증만 분석합니다. 탭 상단에서 LLM 활성 여부·모델·모드·키 설정 여부·이미지 전송 허용 여부를 확인할 수 있습니다. `GET /api/health`에서도 키 값 없이 설정 상태를 확인합니다.

분석이 끝나면 추출값과 지출 초안을 검토하세요. 선택한 영수증의 **분석 이력·현재 값 비교**에서 분석 방식, 모델, 입력/출력 토큰, 추정 비용, 오류 사유를 확인할 수 있습니다. 재분석 후보는 이력에 추가되고 사용자가 저장한 값과 기존 지출 행은 자동으로 덮어쓰지 않습니다. 후보를 적용하려면 검토폼으로 가져온 뒤 저장합니다.

v4 기본인 이미지 분석과 분류를 사용하려면 기존 `.env`에서도 `RECEIPT_LLM_MODE=vision`을 확인하세요. 기존 `.env`의 키와 사용자 설정은 자동으로 바꾸지 않습니다.

| 변수 | 기본값 | 의미 |
|---|---|---|
| `RECEIPT_LLM_ENABLED` | `false` | `true`일 때만 외부 API 호출 허용 |

| 모드 | 동작 | PaddleOCR 필요 여부 |
|---|---|---|
| `vision` | 영수증마다 이미지를 직접 분석. 로컬 OCR 초기화를 건너뜀 | 불필요 |
| `auto` | OCR 필드가 충분하면 추출값을 유지하고 항목 분류만 수행(분류 목록이 없으면 호출 생략). 부족하면 텍스트 보완·분류. 텍스트가 없으면 허용된 경우 이미지 분석·분류 | 이미지 허용 시 없어도 동작 |

### 검토·개인정보·비용과 오류 처리

- 외부로 보내는 OCR 텍스트에는 카드/계좌번호 형태의 긴 숫자, 전화번호, 주민등록번호 형태, 이메일에 대한 규칙 기반 마스킹을 적용합니다. 모든 개인정보 패턴을 완벽하게 탐지하는 것은 아닙니다.
- **이미지는 자동 개인정보 마스킹을 보장하지 않습니다.** 이미지 전송을 허용하면 크기와 방향을 보정하고 메타데이터를 제거한 JPEG를 외부 API로 전송합니다. 원본 파일은 로컬에 유지합니다.
- Responses 요청에는 `store=false`를 사용합니다. 이것이 제공자의 전체 로그·보관 정책을 변경하거나 무보관을 보장하는 의미는 아닙니다.
- JSON 스키마와 서버 검증을 적용합니다. 날짜·시간·금액이 불명확하면 빈 값으로 남기고, 시간이 없을 때 자정을 채우지 않습니다. 외화/불명 통화는 원화 금액으로 확정하지 않습니다. 취소·환불도 사용자 검토가 필요합니다.
- 인증 실패, 사용량 제한, 타임아웃, 응답 거절·미완료·형식 오류는 영수증 검토 사유와 분석 이력에 남기고 다음 영수증 처리를 계속합니다. API 응답 본문의 원문 오류나 API 키를 사용자 오류 메시지에 노출하지 않습니다.
- 자동 재시도는 하지 않습니다. 재분석 버튼을 다시 누르면 추가 API 호출이 발생할 수 있습니다. 기본 응답 출력 제한은 1,600토큰입니다.
- 입력/출력 토큰은 제공자가 반환한 사용량을 기록합니다. 단가 두 개를 설정하면 `(입력 토큰 × 입력 단가 + 출력 토큰 × 출력 단가) / 1,000,000`으로 USD 추정치를 기록합니다. 단가 미설정 시 비용은 미산정으로 표시합니다. 캐시 할인·세금 등을 반영한 청구 금액과는 다를 수 있습니다.

구현 규격은 공식 [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create), [구조화 출력](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses), [GPT-4.1 mini 모델 설명](https://developers.openai.com/api/docs/models/gpt-4.1-mini)을 참고했습니다. 모델 사용 가능 여부와 단가는 자신의 API 계정에서 확인하세요.

## 공통 저장·확정 사용법

1. 행사 생성 후 영수증 탭에서 ZIP을 업로드하고 OCR 분석을 시작합니다.
2. 분석한 영수증으로 지출 초안을 생성합니다. 같은 장부나 행사에서 거래일과 결제금액이 같으면, 거래 시간이 가장 이른 영수증 기준으로 초안을 한 행만 만듭니다. 시간이 없는 건은 시간이 있는 건보다 뒤로 두며, 직접 수정한 지출과 영수증 원본은 보관합니다. 항목을 판단할 수 없으면 행사는 기타, 경상비 장부는 기타 / 기타 / 기타로 임시 분류합니다.
3. 지출내역과 영수증 탭에서 원본·후보값·현재값을 비교하고 수정합니다. 자동 생성된 초안 행은 `검토 완료`를 체크하세요. 영수증 수정은 `검토값 저장`, 지출 수정은 `임시 저장`으로 반영합니다.
4. `임시 저장` 후 `최종 확정`에서 필수값과 검토 상태를 확인합니다. 영수증 미첨부·금액 차이는 승인 사유와 확인을 입력한 후 확정할 수 있습니다.
5. 확정 상태에서는 편집이 잠깁니다. `수정 재오픈`하면 이전 확정본을 유지한 채 재수정할 수 있고 재확정 시 다음 버전이 생성됩니다.
6. `변경 이력` 탭에서 확정 버전별 Excel과 ZIP을 다운로드합니다. 재수정 중 목록 총지출은 마지막 확정본을 표시하고 편집 중 금액은 별도 안내합니다.

확정본이 없으면 화면의 내보내기는 `DRAFT_` 파일명으로 초안을 제공합니다. 확정본이 있으면 기본 내보내기는 최신 확정 버전을 사용합니다. API에서 편집 중 초안을 강제로 내보내려면 `?draft=true`, 특정 확정본은 `?version=1`을 사용하세요.

## 업무 규칙

- 금액은 0 이상의 정수 KRW, 총지출은 구매 여부에 관계없이 모든 지출 합계입니다.
- 날짜 연도 생략은 행사 시작 연도를 제안하고 확인을 요구합니다. 빈 날짜는 바로 앞 날짜를 이어받으며 경고를 표시합니다.
- Excel 계산식의 캐시가 없으면 오류로 표시합니다. Excel에서 재계산 후 저장해 가져오세요.
- 원본 Excel이 제공되지 않아 계획서의 9개 컬럼을 기준으로 서식을 구현했습니다. 불명확한 헤더는 사용자가 열 번호를 지정합니다.
- Excel 영수증 번호·총합은 내보내기 참고값입니다. 가져올 때 이미지나 영수증 연결을 자동으로 생성하지 않습니다.
- 영수증 참조 번호는 행사 또는 메뉴+연도별로 1부터 부여하며, 거래일시를 수정해도 유지됩니다. 지출 행 번호·DB ID 및 ZIP 정렬 순번과는 다릅니다.
- 영수증 총합은 연결별 **배분금액** 합계입니다. 한 영수증의 전체 배분액은 최종 결제금액을 초과할 수 없습니다.
- 정리 ZIP은 거래일시·원본 파일명 순으로 정렬합니다. 정상 영수증은 `receipts/`, 시간·금액 미확인은 `review_required/`, 중복 제외는 `excluded/`에 보관하고 `receipts_summary.csv`를 함께 제공합니다. 원본 이미지 바이트를 유지합니다. 날짜만 입력하면 시간을 생성하지 않습니다. 입력 시각은 한국 현지 시각으로 취급하며 시간대가 명시된 값은 한국 시각으로 변환합니다.
- 행사 복제는 행사·항목·지출을 복사합니다. 원본 영수증과 연결은 복사하지 않습니다.
- 행사 삭제는 관련 지출·항목·영수증·이미지 원본을 삭제합니다.
- 업로드: Excel 15MB, ZIP 60MB, 이미지당 20MB, 총 해제 250MB, ZIP당 이미지 최대 300장. 경로 조작·심볼릭 링크·암호화·고압축률·위장 이미지 파일을 거부합니다.

## 저장 구조와 호환성

- 기존 행사비 데이터와 API를 유지하기 위해 `annual_books`의 `kind`(ordinary/b)+`year`를 유일 키로 사용합니다. 경상비와 B의 같은 연도는 서로 다른 장부입니다.
- 각 장부는 공통 영수증·확정·분석 서비스를 위한 **고유 소유 스코프**를 FK로 가집니다. 행사 목록에는 이 내부 스코프를 표시하지 않습니다. 거래·예산·영수증은 서로 다른 연도/메뉴에 연결할 수 없도록 서비스와 FK 제약을 함께 적용합니다.
- AI 결과와 수정값은 분리하고, 확정 스냅샷에는 연도별 예산·수입/지출·이월 유형·영수증·배분액을 포함합니다. 확정 당시 이미지는 별도 사본으로 보관합니다.
- 같은 파일의 다른 장부 재사용은 SHA-256으로 경고합니다. 승인한 대상에는 독립된 영수증 ID·메타데이터를 만들어 한 장부의 수정을 다른 장부에 전파하지 않습니다. 원본은 `storage/receipts/event/<행사ID>/` 또는 `storage/receipts/<ordinary|b>/<연도>/<소유스코프ID>/`에 구분 저장하며 기존 파일 경로도 유지합니다. 확정본에 사용했던 영수증 참조 번호는 원본을 삭제한 뒤에도 새 영수증에 재사용하지 않습니다.
- `GET /api/analysis-jobs/{id}`에서 작업별 입력/출력 토큰·추정 비용·미산정 건수·분석 오류 건수를 조회합니다. 기존 `/api/jobs/{id}`도 같은 집계를 제공합니다. v4 이전 분석 이력에는 작업 연결 정보가 없으므로 신규 작업부터 집계됩니다.
- 업그레이드 전 자동 SQLite 백업은 `storage/backups/`에 생성됩니다. 이는 DB 백업이며 전체 복구용 원본 이미지까지 보관하려면 서버를 멈추고 `storage/` 전체를 복사하세요.

### 별도 QA 환경

사용자가 실행 중인 개발 서버와 함께 검증할 때는 DB·포트·Next.js 빌드 캐시를 모두 분리하세요. 기본 실행값은 바뀌지 않습니다.

```bash
# 프로젝트 루트, 임시 DB / 유료 호출 비활성화
RECEIPT_LLM_ENABLED=false STORAGE_DIR=/tmp/bpmc-v4-qa DATABASE_URL=sqlite:////tmp/bpmc-v4-qa/expense.db .venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8011
# 다른 터미널, frontend/ 디렉터리
NEXT_DIST_DIR=.next-qa API_BASE_URL=http://127.0.0.1:8011 npm run dev -- --port 3011
# frontend/에서 테스트
PLAYWRIGHT_BASE_URL=http://127.0.0.1:3011 npm run test:e2e
```

`.next-qa/`는 Git에서 제외합니다. 외부 유료 LLM은 테스트에서 항상 비활성화하거나 모의 응답을 사용합니다. 실제 사용자 DB를 테스트 대상으로 쓰지 마세요.

## 현재 한계와 후속 작업

- 실제 원본 `.xlsx` 및 실제 영수증 표본이 없어 원본 서식 정밀 대응, OCR 정확도와 50장 처리시간은 아직 검증하지 못했습니다.
- 외부 LLM 호출·응답 검증·사용량 기록은 모의 API로 검증했습니다. 실제 API 키를 이용한 유료 호출과 실제 영수증 정확도는 아직 검증하지 못했습니다.
- 로그인·사용자 권한은 초기 개인용 범위에서 제외했습니다. 기본 실행과 Compose는 로컬 접근용입니다.
- 데이터 백업은 서버를 멈춘 뒤 `storage/` 전체를 복사하세요. 복구도 서버를 멈추고 해당 폴더를 복원합니다.

## Excel 가져오기 샘플 양식

각 **Excel 가져오기** 창의 **샘플 양식 다운로드** 버튼에서 `.xlsx` 파일을 받습니다.

- 행사비: 지출일·항목·품목·총계·구매처 등이 포함된 지출내역 양식. 현재 행사의 활성 항목명을 예시에 반영합니다.
- 경상비 예산 현황: 관·항·목·예산·세부내용 양식.
- 경상비 장부: 날짜·항·목·내용·수입·지출·영수증번호 양식. 현재 연도와 등록된 활성 목을 예시에 반영합니다.
- B 장부: 날짜·내용·수입·지출·영수증번호 양식. 이월금·일반 수입·지출·캐시백 예시를 제공합니다.

샘플의 **작성 안내** 시트를 읽고 예시 행을 실제 자료로 바꾸거나 삭제하세요. 예시 행도 가져오기 대상입니다. 열 제목은 유지하고 금액은 수식 없이 원 단위 정수로 입력합니다. 영수증번호를 적어도 영수증 연결이 자동 생성되지는 않습니다. 파일 선택 후 미리보기에서 검토하고 반영합니다. 샘플 다운로드는 저장된 장부를 변경하지 않습니다.

경상비 장부 Excel에서 항·목이 비어 있거나 등록된 예산 항목과 일치하지 않는 경우에도 가져올 수 있습니다. 해당 행은 **기타 / 기타 / 기타**로 임시 분류하고 **검토 필요**로 표시합니다. 미리보기와 장부 행에 임시 분류가 표시되며, 원본 분류명과 Excel 행 번호는 거래 메모에 보존됩니다. 기타 예산 계층은 반영 시에만 생성하며 기존 항목이 있으면 재사용합니다. 정상적으로 일치하는 항·목은 그대로 유지합니다.
